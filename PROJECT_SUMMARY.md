# QKD Poisoning Detection with Machine Learning

## 1. Project purpose

This project studies whether machine-learning models can distinguish clean BB84 quantum-key-distribution (QKD) traffic from traffic affected by several poisoning or manipulation strategies.

The central task is a binary classification problem:

- **Clean class (`label = 0`)**: simulated BB84 traffic with an Eve intercept-resend attack.
- **Poisoned class (`label = 1`)**: the same type of traffic after a controlled poisoning transformation.

The work has progressed from an earlier, smaller poisoning study to a deterministic 100,000-batch dataset and a reproducible multi-model evaluation pipeline.

## 2. Dataset and simulation setup

The current final dataset is generated by [`src/generate_clean_dataset.py`](src/generate_clean_dataset.py).

The main configuration is:

- 100,000 batches
- 500 keys per batch
- 8-bit keys
- BB84-style simulation
- Eve intercept-resend attack applied to every key
- Random seed `42`
- Per-key mismatch count in the range `0..8`

Under this simulation, a clean key's mismatch count follows the intended Binomial distribution:

```text
Binomial(8, 0.25)
```

The raw per-key experiment would contain 50 million key records. To keep the project manageable and preserve the information required by the classifiers, the repository stores lossless batch histograms instead:

```text
count_0, count_1, ..., count_8
```

Here, `count_k` is the number of keys in a batch with exactly `k` mismatched bits. The clean dataset also stores the derived feature columns.

The generated clean file is:

```text
paper/clean_batches_500keys.csv
```

The clean class contains 100,000 batches. Each poisoned approach contains five poisoning levels stacked into one file, giving 500,000 rows per approach.

## 3. Poisoning approaches implemented

The common poisoning driver is implemented in [`src/poison_common.py`](src/poison_common.py). Each approach starts from the same deterministic clean mismatch stream and uses a reproducible random generator.

The poisoning levels are:

```text
10%, 20%, 30%, 40%, 50%
```

The percentage means the percentage of all key rows selected for modification. Selection is uniform and without replacement. The modified batches retain the original batch identifiers.

### Approach A: Random resampling

Implemented in [`src/poison_approach_A.py`](src/poison_approach_A.py).

For selected keys, the mismatch count is replaced by a fresh uniformly distributed integer from `0` through `8`.

Expected effect:

- Strongly changes the mismatch histogram
- Creates unusually frequent high-mismatch values
- Usually makes poisoning easy to detect

### Approach B: Symmetric random `+/-1` shift

Implemented in [`src/poison_approach_B.py`](src/poison_approach_B.py).

For selected keys, the mismatch count is shifted by either `+1` or `-1` with equal probability, then clipped to the valid range `0..8`.

Expected effect:

- Keeps the average QBER comparatively stable
- Changes the distribution more subtly
- Tests whether models can detect a stealthier manipulation

This became the most difficult case in the current results, especially at the lowest poisoning level.

### Approach C: `+1` availability-oriented attack

Implemented in [`src/poison_approach_C.py`](src/poison_approach_C.py).

For selected keys, one mismatch is added and the result is clipped at `8`.

Expected effect:

- Raises the measured error rate
- Makes a legitimate session appear noisier
- Represents an availability-style attack that may cause a key exchange to be aborted

### Approach D: `-1` stealth-oriented attack

Implemented in [`src/poison_approach_D.py`](src/poison_approach_D.py).

For selected keys, one mismatch is removed and the result is clipped at `0`.

Expected effect:

- Lowers the measured error rate
- Hides part of the observed error signal
- Represents a stealth-oriented manipulation

## 4. Feature engineering

Feature extraction is defined in `features_from_counts()` in [`src/generate_clean_dataset.py`](src/generate_clean_dataset.py).

Each batch is converted into 15 distribution features:

1. Mean QBER
2. Standard deviation of QBER
3. QBER skewness
4. QBER kurtosis
5. Nine QBER-bin fractions corresponding to mismatch counts `0..8`
6. Chi-square statistic against the theoretical Binomial distribution
7. Kolmogorov-Smirnov-style cumulative-distribution distance

All features are derived from the `count_0..count_8` histogram. This means the poisoned files do not need to store the 50 million individual key records to support the experiment.

## 5. Aggregation and classification protocol

The model pipeline is shared by [`src/models/model_common.py`](src/models/model_common.py).

The evaluation procedure is:

1. Load the clean histogram dataset.
2. Load one poisoned approach and one poisoning level.
3. Recompute the same 15 features for the poisoned data.
4. Aggregate every five consecutive batches into one sample.
5. Combine clean samples and poisoned samples into a binary dataset.
6. Use an 80/20 stratified train/test split with `random_state=42`.
7. Fit `StandardScaler` on the training portion only.
8. Train the selected classifier.
9. Compute:
   - Accuracy
   - ROC AUC
   - Confusion matrix
   - ROC false-positive-rate and true-positive-rate arrays
   - Training time
10. Save the result after each combination so interrupted experiments can resume.

The aggregation window reduces the 100,000 batches in each class to 20,000 aggregated samples per experiment before the train/test split.

## 6. Models evaluated

The following six classifiers are implemented and evaluated:

- Logistic Regression
- Random Forest
- K-Nearest Neighbours
- Gradient Boosting
- Support Vector Machine
- Neural Network

The individual model wrappers are in [`src/models/`](src/models/). The complete pipeline is launched by [`src/models/run_all_models.py`](src/models/run_all_models.py).

The current experiment size is:

```text
6 models x 4 poisoning approaches x 5 poisoning levels
= 120 model evaluations
```

## 7. Current results

The combined results are stored in [`results/combined/`](results/combined/), especially:

- `all_results_long.csv`
- `accuracy_table.csv`
- `auc_table.csv`
- `summary.txt`

The current run contains 120 model evaluations.

### Overall model-level averages

The current aggregate results are:

| Model | Mean accuracy | Mean AUC | Minimum accuracy | Minimum AUC |
|---|---:|---:|---:|---:|
| Random Forest | 0.9884 | 0.9949 | 0.8340 | 0.9076 |
| Gradient Boosting | 0.9887 | 0.9954 | 0.8382 | 0.9144 |
| Logistic Regression | 0.9887 | 0.9955 | 0.8394 | 0.9155 |
| SVM | 0.9886 | 0.9948 | 0.8359 | 0.9033 |
| KNN | 0.9864 | 0.9922 | 0.8056 | 0.8696 |
| Neural Network | 0.9886 | 0.9954 | 0.8389 | 0.9145 |

These are averages across all four approaches and all five poisoning levels. They should not be interpreted as performance on one universal real-world distribution.

### Most difficult observed condition

The most difficult tested condition was:

```text
Approach B at 10% poisoning
```

Approximate results for this condition were:

- Accuracy range across models: `0.8056` to `0.8394`
- AUC range across models: `0.8696` to `0.9155`

At higher poisoning levels, performance generally improves because the distributional effect becomes easier to distinguish. Approaches A, C, and D are generally easier to detect than the symmetric `+/-1` approach at the lowest level.

These figures are empirical outputs of the current simulation and should not be presented as a guarantee of performance against operational QKD traffic.

## 8. Results and figure generation

The current figure generator is [`src/models/make_figures.py`](src/models/make_figures.py).

It reads the saved JSON model outputs rather than using manually entered or synthetic plotting values. For each figure, both PNG and vector PDF versions are written to [`results/figures/`](results/figures/).

The current set contains 12 figure types:

1. Accuracy by poisoning level
2. AUC by poisoning level
3. Accuracy heatmaps
4. AUC heatmaps
5. Accuracy comparison at the lowest level
6. AUC comparison at the lowest level
7. Accuracy distribution across experiments
8. AUC distribution across experiments
9. Mean classification error
10. Training time by poisoning level
11. ROC curves for Approach B at the lowest level
12. Confusion matrices for Approach B at the lowest level

The full pipeline can be rerun from the repository root with:

```powershell
& ".venv\Scripts\python.exe" "src\models\run_all_models.py"
```

The command runs the model scripts, combines the results, and regenerates the figures.
